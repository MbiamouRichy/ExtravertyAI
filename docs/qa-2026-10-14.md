## Défauts et points à traiter

### P1 — Débloquer la recette de préproduction

Les trois tests API existants échouent : connexion attendue en 200, reçue en 302 ; webhooks attendus en 400, reçus en 401. Le lien seul ne donne pas accès aux tests automatisés. Au dernier contrôle, `.env.e2e.local` ne contenait ni compte de test complet ni secret de bypass.

Configurer localement `E2E_VERCEL_BYPASS_SECRET`, `E2E_EMAIL` et `E2E_PASSWORD`. Le secret de bypass du webhook Stripe doit être traité séparément, conformément à `docs/tests-preview.md`. Ces résultats ne prouvent pas que la destination Stripe réelle est mal configurée : celle-ci reste à vérifier avec son propre accès.

### P2 — Bouton de visibilité du mot de passe sans nom accessible

Sur `/sign-in`, le contrôle contenant uniquement l'icône Eye/EyeOff est annoncé comme un bouton sans nom. Confirmé dans le code (`components/auth/signInPage.tsx`, vers la ligne 184) et dans l'arbre d'accessibilité Playwright. Un utilisateur de lecteur d'écran ne peut pas identifier sa fonction.

Correction attendue : nom accessible « Afficher le mot de passe » / « Masquer le mot de passe », état cohérent et fonctionnement clavier. Le nouveau scénario de test documente cette attente.

### P2 — Connexion TikTok proposée alors que la configuration locale manque

Le build et le serveur avertissent que les identifiants TikTok manquent ; le bouton reste présent dans `components/auth/signInSocialButton.tsx`. Constat limité à l'environnement local, pas une preuve sur la préproduction. Vérifier la configuration de recette et masquer ou désactiver clairement une connexion non disponible.

### Outillage — ESLint parcourt des fichiers temporaires

Le lint global initial s'arrête sur `EPERM` dans `.scratch/python-deps/bcrypt`. Ce dossier est ignoré par Git mais pas par la configuration ESLint. Le contrôle des seuls répertoires sources a été relancé séparément. L'erreur initiale ne constitue pas une erreur applicative.

## Limites et interprétation

Le premier passage navigateur a subi des délais au démarrage et une attente `networkidle` inadaptée à des ressources externes. Un sélecteur du test de petit écran a également été corrigé. Ces échecs ne sont pas tous des défauts produit : un second passage utilise le DOM et le serveur déjà démarré.

Le serveur a enregistré un délai sur l'image distante `storage.efferd.com/screen/dashboard-light.webp`. La disponibilité de cette ressource et son repli visuel restent à vérifier.

La première vérification TypeScript autonome a rencontré des fichiers `.next/types` en cours de régénération par le build ; ce résultat concurrent n'est pas retenu comme défaut. Le contrôle TypeScript intégré au build a ensuite réussi.

Les parcours connectés, l'isolation réelle entre deux comptes, le paiement et ses retours, l'arrivée effective des webhooks, l'envoi WhatsApp, les emails et la reprise après incident restent à exécuter en préproduction avec des données dédiées. Pas de mesure de charge ni de certification de sécurité complète.

## Résultat final des parcours navigateur locaux

**18 scénarios exécutés : 14 réussis, 4 échecs.** Les quatre échecs correspondent à deux défauts reproduits dans les deux profils Playwright (Desktop Chrome sur Edge et Pixel 7 sur Edge).

- Accueil, Contact, À propos, Connexion et Inscription : contrôles de rendu, langue française, erreurs JavaScript non interceptées et débordement horizontal réussis sur ordinateur et mobile.
- Validation de connexion sans envoi et redirection de `/projects/new` vers la connexion : réussies sur ordinateur et mobile.
- Bouton de visibilité du mot de passe : échec dans les deux profils, nom accessible absent.
- Écran court de 375 × 400 px : échec dans les deux profils, lien `Accueil` hors viewport, ratio de visibilité 0 même après `scrollIntoViewIfNeeded`.

### P2 — Navigation coupée sur petit écran

Reproduction : ouvrir `/sign-in` avec un viewport de 375 × 400 px ; tenter d'atteindre le lien Accueil en haut du formulaire. Le lien est trouvé dans le DOM mais reste invisible après tentative de défilement. Le conteneur utilise `h-screen`, centrage vertical et `overflow-hidden` (`components/auth/signInPage.tsx`, ligne 104).

Correction attendue : laisser le contenu dépasser en hauteur avec un défilement vertical utilisable et vérifier le fonctionnement avec clavier virtuel/zoom. Le test de petit écran est conservé dans `tests/e2e/public-quality.browser.spec.ts`.

### État des contrôles restants

- Contrôle HTTP final après démarrage : **9/9 réussis** (7 API refusant une session absente + 2 webhooks rejetant l'absence de secret/signature).
- ESLint : **non validé**. Le lint global échoue sur un dossier temporaire ; les tentatives ciblées sur les sources n'ont pas rendu de résultat exploitable et ont été interrompues. Ne pas considérer le lint comme réussi.
- Test isolé de synchronisation de thème : délai de 120 secondes dépassé lors du premier passage ; pas de conclusion fonctionnelle, à relancer sur un environnement stable. Il n'est pas inclus dans les 18 scénarios applicatifs finaux.
- Capture visuelle : tentative interrompue après dépassement du délai de capture ; les assertions DOM ne remplacent pas une revue visuelle complète.
- Accès de préproduction : dernier contrôle toujours HTTP 302 vers Vercel, sans compte ni bypass configurés dans le fichier de recette local.
